# OpenCrab 앱형 워크플로우 팩 상품화 설계

> 모드: design-only. 판매 구조 설계만, 실제 결제/배포/외부전송 구현 없음.

---

## 1. 왜 ZIP 팩만 팔면 약한가

현재 OpenCrab Pack v1은 ZIP(graph/evidence/quality)이다. ZIP만 파는 모델의 한계:
- 구매자가 **그래프를 직접 질의할 도구**가 있어야만 가치 발생 → 일반 사용자 진입장벽.
- "데이터"는 복제·재판매 리스크에 노출되고, 가공가치를 방어하기 어렵다.
- 1회성 판매 → 반복 과금(구독) 근거가 약하다.
- 구매자가 "그래서 뭘 하면 되는가"를 모름 → 결과물까지의 워크플로우가 빠져있음.

agent-native의 통찰: **데이터가 아니라 "행동(action) + 화면(plan/recap)"을 팔면** 사용자는 버튼만 누르면 결과가 나온다. 가공 로직은 서버에 남아 재판매가 어렵다.

---

## 2. 앱형 워크플로우 상품 구조

```
유료팩 상품 = Pack(ZIP)  +  Pack Action Contract 세트
            +  Visual Plan/Recap 화면
            +  실행 버튼(UI/AI/MCP/API 공통)
            +  결과 리포트 템플릿
            +  evidence gate / review gate
```

판매 단위는 "ZIP"이 아니라 **"문제를 푸는 앱"**. 구매자는 입력만 주면 Visual Plan→preview→Recap→리포트를 받는다. 원천 evidence·가공 로직은 서버에 남고, 구매자에겐 결과물 + 출처 링크만 제공(원본 재판매 방지).

agent-native `templates/` 모델 차용: 각 상품 = "복제 가능한 앱 템플릿". 단, OpenCrab은 **preview_only·사람승인** 게이트를 기본 내장.

---

## 3. 유료팩 상품 템플릿 (공통 기재 항목)

```
상품명:
대상 사용자:
핵심 문제:
제공 기능:
사용하는 팩(pack_id):
사용하는 action(action_id[]):
결과물:
과금 포인트:
위험/제한사항:
```

## 4. 입찰 검토 자동화 앱

- **상품명**: 입찰 검토 자동화 앱
- **대상**: 관급공사·물품 입찰 참여 소상공인/중소기업
- **핵심 문제**: 하루 수백 공고 중 "우리가 자격되는 것"을 빠르게 거르고, 제출서류를 빠짐없이 챙기기
- **제공 기능**: 공고 핵심조건 추출 → 자격충족 판정 → 제출 체크리스트
- **팩**: `bid_review_pack`
- **action**: `analyze_bid_notice`, `check_qualification`, `generate_submission_checklist`
- **결과물**: 공고 요약 리포트 + 자격충족표 + 마감 알림 체크리스트
- **과금**: 월 구독(공고 분석 건수 구간제) + 자격판정 프리미엄
- **위험/제한**: 자격판정은 "참고"이며 최종 책임은 사용자. evidence 없는 판정 차단. 자동 투찰 없음.

## 5. 제주 여행 일정 자동 생성 앱

- **상품명**: 제주 여행 일정 자동 생성 앱
- **대상**: 가족·소그룹 자유여행객
- **핵심 문제**: 어디·언제·동선·숙소·맛집·예산·우천대체를 한 번에 짜기 어려움
- **제공 기능**: 일정 초안 생성 → 시점별 혼잡도 → 좌표 기반 동선
- **팩**: `travel_pack`
- **action**: `build_trip_plan`, `check_crowding`, `recommend_route`
- **결과물**: 일자별 일정 + 동선지도 + 예산표 + 우천 대체안
- **과금**: 일정 1건당 단건 결제 or 지역팩 묶음 구독
- **위험/제한**: 공공/공식 API 사실데이터만(좌표·시간·가격). typical vs current 분리·`observed_at` 명시. 원문/사진 미저장, 출처 링크 제공.

## 6. 특허 선행기술 검토 앱

- **상품명**: 특허 선행기술 검토 앱
- **대상**: 스타트업 IP 담당·개인 발명가·변리사 보조
- **핵심 문제**: 청구항 분해·선행기술 대비·거절대응 개요 작성이 시간 소모
- **제공 기능**: 청구항 구성요소 분해 → 선행기술 대비표 → 거절대응 개요 초안
- **팩**: `patent_pack`
- **action**: `extract_claim_elements`, `compare_prior_art`, `generate_rejection_response_outline`
- **결과물**: 청구항 트리 + 대비 매트릭스 + 대응 개요(초안)
- **과금**: 건당 분석 + 대응 개요 프리미엄
- **위험/제한**: **법적 판단 아님 — 변리사/변호사 검토 전제**. 거절대응 개요는 high risk, evidence 없는 법적 주장 금지.

## 7. 아파트 외벽 컬러 제안서 생성 앱

- **상품명**: 아파트 외벽 컬러 제안서 생성 앱
- **대상**: 도장 시공사·관리사무소·리모델링 영업
- **핵심 문제**: 사진 한 장으로 컬러 시안·물량·제안서를 빠르게 뽑기
- **제공 기능**: 외벽 사진 분할 → 도료 컬러 매핑 → 제안서 생성
- **팩**: `facade_design_pack`
- **action**: `segment_building_photo`, `map_paint_colors`, `generate_design_proposal`
- **결과물**: 컬러 시안 이미지 + 물량 추정 + 제안서 문서(초안)
- **과금**: 제안서 1건당 결제 + 컬러팔레트 구독
- **위험/제한**: 물량은 "참고 견적"(현장 실측 필요). 사진 evidence 필수.

## 8. 고기집 창업 콘셉트 설계 앱

- **상품명**: 고기집 창업 콘셉트 설계 앱
- **대상**: 외식 창업 예정자·소규모 프랜차이즈
- **핵심 문제**: 상권·컨셉·메뉴·매장배치를 데이터로 검증하고 싶음
- **제공 기능**: 상권/컨셉 적합도 → 메뉴 시스템 → 매장 레이아웃
- **팩**: `restaurant_startup_pack`
- **action**: `analyze_local_concept`, `generate_menu_system`, `create_store_layout_plan`
- **결과물**: 상권 분석 리포트 + 메뉴·원가표 + 매장 배치도(초안)
- **과금**: 콘셉트 패키지 단건 + 업데이트 구독
- **위험/제한**: 사업 의사결정 보조 도구(투자 권유 아님). 데이터 출처·시점 명시.

## 9. 가격 책정 포인트

| 과금 모델 | 적용 | 근거 |
|---|---|---|
| **건당 결제** | 여행 일정, 제안서, 콘셉트 패키지 | 1회성 산출물 가치 명확 |
| **구간 구독** | 입찰 공고 분석(건수) | 반복 사용·업데이트 가치 |
| **프리미엄 add-on** | 자격판정·거절대응 개요 | high-value/high-risk 판단 |
| **팩 라이선스** | pack ZIP + action 세트 묶음 | B2B(시공사·법무) 재배포 |

가치 방어: evidence 원본·가공 로직은 서버에 남기고, 구매자에겐 **결과물 + 출처 포인터**만. ZIP 재판매가 아니라 "행동 실행권"을 판매.

---

## 10. 운영/유지보수 포인트

- **evidence freshness**: `observed_at` 기반, 만료 시 Visual Plan에 `stale` 플래그.
- **pack 버전 관리**: manifest `version`·`grammar_version`. 업데이트는 새 promotion 아티팩트(ZIP)로.
- **품질 게이트**: Pack v1 `quality/report.json`(evidence_coverage·node_evidence_integrity) 1.0 미만 상품은 출시 보류.
- **사람 승인 운영**: approvals 큐 적체 모니터링(빙구팩 notification_queue 패턴 재사용).
- **합법성**: 공공/공식 API·사실데이터·가공판매. 크롤링 원문 재판매 금지(패소판례). private pack 원본 외부 전송 금지.
